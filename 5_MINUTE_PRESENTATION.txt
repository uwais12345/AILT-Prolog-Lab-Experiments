MINUTE 2: KNOWLEDGE REPRESENTATION & RULES (1:00 - 2:00)
================================================================================
[SAY THIS]:
"Our system operates strictly on first-order logic and Horn clauses. 

We represent domain knowledge as declarative facts:
1. Product categories: category(pizza, fast_food), category(mobile, electronics).
2. Customer transactions: purchased(user1, pizza), purchased(user2, mobile).
3. Complementary relationships: related(mobile, mobile_case), related(mobile, charger).
4. Co-purchase frequencies: frequently_bought(milk, bread), frequently_bought(milk, eggs).

From these facts, we define logical inference rules:
- 'likes_category(User, Category)': deduces customer preferences by inspecting 
  historical purchases.
- 'recommend_by_category(User, Product)': uses Negation-as-Failure to recommend items 
  matching that category which the user has not yet purchased.
- 'recommend_related/2' and 'recommend_frequently_bought/2': infer targeted accessories 
  and complementary bundles.
- 'placement_suggestion/2': translates co-purchase relationships into merchandising intelligence."

MINUTE 5: BACKTRACKING & CONCLUSION (4:00 - 5:00)
================================================================================
[ACTION ON TERMINAL]:
Press '11' for 'Backtracking Demonstration'.

[SAY THIS]:
"Finally, we highlight Prolog's core algorithmic superpower: Chronological Backtracking.

On screen, you see the query: '?- recommend_related(user2, Product).'
Prolog searches the knowledge base, unifies Product with 'mobile_case', and returns 
Solution 1. Upon seeking alternative solutions, Prolog backtracks to the choice point 
and unifies Product with 'tempered_glass', then 'charger', before exhausting all clauses 
and terminating with 'false.'.

We can also exit the application cleanly via Option '0', and run these exact queries 
directly in the top-level interpreter:
?- recommend_by_category(user1, P).

In summary, this project proves that classical logic programming provides an efficient, 
transparent, and maintainable foundation for intelligent decision support systems. 

Thank you, Professor. I am now ready for your questions!"

QUICK VIVA CHEAT SHEET (IF ASKED RAPID QUESTIONS):
--------------------------------------------------------------------------------
Q: Why use Prolog over Machine Learning?
A: Explainability, deterministic results, zero training time, no large dataset needed.

Q: How does Prolog search for answers?
A: Depth-First Search with Chronological Backtracking and Robinson's Unification Algorithm.

Q: What is Closed-World Assumption?
A: Any statement not provable from facts and rules is assumed to be false (\+ operator).

Q: How is session state maintained?
A: Through dynamic predicates: current_user/1 and purchased/2 using assertz and retractall.
